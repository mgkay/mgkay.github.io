track-changes v4: import-verification rethink. verified-import's mechanical content-word gate is removed — a /import now lands clean by default via a one-shot sha-bound exemption that track-changes consumes, and the LLM self-marks only genuinely significant changes (an added or removed sentence or clause, or a changed quantity, term, or formula; reflow, formatting, and equivalent notation are not significant). This fixes cross-format false-rejections — e.g. a faithful LaTeX-to-Markdown import of an equation like Q* = sqrt(2KD/h) — that the v3 token-multiset gate could never accept, because the two formats tokenize the same math differently. The /import CLI now strips a leading @ file-reference prefix and emits UTF-8, so math symbols and em-dashes no longer mangle on a Windows console. The track-changes mark core is unchanged and existing tracked documents need no conversion; the text-source-only contract stays. SC3 (significant changes are surfaced for review) is a behavioral contract — significance is the model's judgment, verified by mechanism tests, with no mechanical backstop. 379/379 tests pass.
