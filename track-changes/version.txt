9.1.1
2026-07-12
track-changes v9.1.1 — contextual gray excerpts with a marked source anchor (additive).
- A gray `.tc-verbatim` excerpt may now carry a CONTIGUOUS passage of surrounding source context
  (so a reviewer can place the attribution without reopening the source), with the load-bearing
  sentence — the part actually proposed as the source — wrapped in a source-anchor marker:
  md/qmd `[sentence]{.tc-src-key}`, LaTeX `\tcsrckey{sentence}`. The whole block stays gray (all of
  it is verbatim source); the anchor is emphasized (bold + underline, no new color).
- The write-time containment check STRIPS the anchor marker syntax before verifying, so an anchored
  excerpt still verifies verbatim against the plain source; only the syntax is removed — the inner
  text must still be contained, so an anchor cannot smuggle non-source text. The durable audit /
  manifest excerpt records the clean (anchor-stripped) text.
- Guidance (no gate change): the `/tc source` instruction now asks for a contiguous+anchored excerpt
  and reminds that a sourced region must stay SCOPED to what the source supports — an inference built
  on top of the source is authored (uncited) content, not sourced, so a single citation never creeps
  over unsupported claims.
- Purely presentational + guidance; no new hooks (stays 6); backward-compatible (excerpts without an
  anchor are unchanged); no new shipped files; no document migration.

9.1.0
2026-07-12
track-changes v9.1.0 — ironclad sourced-region enforcement (behavior-changing).
- `tc-prov="sourced"` is now an ALWAYS-VERIFIED, ALWAYS-CITED claim, enforced at the write so
  it holds against an uncooperative/forgetful AI agent (not by prompt discipline):
  - The gate now triggers on a new gray `.tc-verbatim` excerpt OR a touched sourced region. A
    sourced region can no longer bypass verification by omitting the gray excerpt (the v9.0
    hole): a brand-new sourced region and its verified gray excerpt must land as ONE pair.
  - The surviving green region MUST carry a reader-facing citation (tc-src is invisible
    metadata, stripped on `/tc accept`). Rule A: staged by `@citekey` → the region must cite
    THAT key (`[@key]` md / `\cite{key}` tex). Rule B: otherwise → any citation/footnote token
    (`[@key]`/`@key`/`^[...]` md; `\cite`-family/`\footnote` tex). Citations buried in code
    spans, HTML/LaTeX comments, or verbatim/`\verb` do NOT count (they render nothing).
  - Editing an already-present sourced region needs no re-staging but must keep a citation — a
    confirmed sourced passage cannot be edited into an unattributed one.
- New shared lib `tc_core/cite.py` (data-only citation detector). `/tc source` instruction now
  tells the agent to include the citation (the exact key when staged by key).
- Additive/back-compat grammar; no new hooks (stays 6); no document migration. Adversarially
  red-teamed (a comment-buried-citation bypass was found and closed).

9.0.0
2026-07-12
track-changes v9.0.0 — source-validation discipline, suite-wide.
- SOURCE-VALIDATION DISCIPLINE: AI text supported by a document source lands as a green
  `sourced` region beside a temporary gray `.tc-verbatim` excerpt that is verbatim BY
  CONSTRUCTION — `/tc source` stages the slice and the PreToolUse hook re-reads the source at
  write time, refusing a fabricated or paraphrased excerpt (exit 2). Containment is
  normalized-exact (NFKC fold, soft-hyphen/ligature/line-break-join, whitespace collapse); a
  scanned/unreadable source fails closed. Sources: text (`.md`/`.qmd`/`.tex`/`.txt`), `.pdf`
  (PyMuPDF), `.docx` (python-docx).
- PROVENANCE + tc-src: `tc-prov="sourced"` joins authored/imported/transcript; a sourced
  region carries `tc-src` binding it to `path#locator` or an `@citekey locator` resolved via
  the document's `.bib` `file`/`localfile` field or a `.tc-sources.json` map (unresolvable
  keys fail closed, naming both mechanisms).
- /tc manifest [<doc>]: regenerates `validation/<stem>.sources.md` whole-file and
  deterministically from the `sourced:` audit entries in `.tc-history.md` — one section per
  region (source, locator, verbatim excerpt, supported text, links both ways) plus a
  "Resolved/removed regions" list. Machine-generated evidence, never model-reconstructed.
- tools/annotate_source_pdf.py: highlights each verified excerpt in an annotated PDF TWIN
  (never the original) under `validation/`, regenerates a trailing summary page, and reports
  every unmatched excerpt (nonzero exit); image-only PDFs are reported and skipped.
- LaTeX first-class: `tcregion` gains an optional trailing src arg (`{N}[prov][src]`, xparse
  `m o o` — absent second optional leaves every v6/v7 parse untouched) plus a `tcverbatim`
  gray-scaffolding environment and green transcript/sourced change-bars. Suite-shipped
  `tc-clean.css` styles all four provenances + `.tc-verbatim` under both raw and `data-`
  attribute forms (a course `_quarto.yml` can shrink to a thin consumer).
- Additive and backward-compatible: mark grammar unchanged (absent provenance/src = authored);
  no new hooks (suite stays at 6); no document migration.

8.2.0
2026-07-12
track-changes v8.2.0 — import-fidelity coverage check for verified-import.
- COVERAGE GATE: a verified import can no longer silently drop source content (the recurring
  "translated only part of a slide" failure, e.g. dropping r_f of four rates). New shared lib
  tc_core/coverage.py compares CONTENT TOKENS (words >=4 letters minus stoplist, numbers >=2
  significant chars, subscripted ids like r_f) with formatting normalized away — reformatting
  passes, dropped content blocks (hook exit 2, missing tokens named, pending import preserved
  for a corrected retry). Fail-closed when the source cannot be re-read at write time.
- OVERRIDE: /tc import --allow-partial stores allow_partial on the pending record; the hook
  then lands the write and records the override + dropped list in the audit entry.
- AUDIT: new /tc coverage <doc> <source> [--units N,N,...] reports per-unit % covered and
  missing tokens (--slides accepted as alias); exit non-zero on any drop.
- Additive and backward-compatible: optional pending-record key; import behavior otherwise
  unchanged; no new hooks (suite stays at 6); no document migration.

8.1.0
2026-07-12
track-changes v8.1.0 — committed-content invariant + transcript provenance.
- RESOLUTION GATE: accept/reject/accept-all/reject-all now REFUSE (exit 3) if the target
  file has uncommitted changes or is untracked (tc_require_clean in lib/tc-cli.sh). An open
  mark is editable right up to resolution, so approval could otherwise attach to content the
  reviewer never read (observed live: an AI polish correction applied and accepted in one
  step). Enforced sequence: commit instructor tweaks (own commit) -> commit AI corrections
  as MARKED edits (own commit) -> review diffs -> resolve. list is not gated; TC_FORCE=1 is
  a human-only override; fail-open outside a git repo. No new hooks; suite stays at 6.
- PROVENANCE (v7 work, first published here): tc-prov="transcript" joins authored/imported
  in tc_core/grammar.py PROV_VALUES — AI wording over the instructor's own class-recording
  transcript content; conventionally paired with a TEMPORARY .tc-verbatim scaffolding block
  (delete after confirming). Documented in SKILL.md (Provenance, Fix E extended) + digest.
- Mark grammar note (from the same incident): the <s>OLD</s> form cannot re-present an
  already-applied change for approval (OLD must still exist in the file) — the rule is that
  polish corrections are marked BEFORE resolution, never applied during it.
