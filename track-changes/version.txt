track-changes v6.0.0 — tracking-enforcement hardening. Closes the recurring hole where AI-authored content reached a tracked deliverable UNTRACKED. (A) Everything the AI writes into a tracked deliverable is now tracked regardless of approval — the "approval is the audit trail" conflation is removed (authorization and verification are separate gates that both always hold). (B) /draft is mechanically USER-ONLY: the per-turn suspension sentinel is written solely by the UserPromptSubmit hook when the human's own prompt requests it (carrying an authorized marker the PreToolUse gate requires); lib/draft-on.sh no longer writes it and a forged/bare sentinel is ignored, so the AI can no longer suspend its own tracking. (D) New whole-region insertion mode — a multi-block new region marks as ONE tracked unit: a Quarto `::: {.tc-region tc-n="N" tc-prov="..."}` … `:::` fenced div, or a LaTeX `tcregion` environment that draws a left change-bar (robust across display math and verbatim); `/tc accept|reject N` resolves it atomically. (E) Provenance-typed marks: `tc-prov="authored"` (default) vs `"imported"` (a verbatim /import slice), with distinct render colors. Plus the corpus-example convention (import the lifted scenario; track the new Julia/prose as authored). BREAKING (behavior, not format): the AI can no longer suspend tracking via /draft or draft-on.sh — only the user can. The mark grammar is BACKWARD-COMPATIBLE — every v1–v5 mark and document parses unchanged (absent provenance = authored); no document migration. No new hooks (the suite stays at 6); no settings change beyond the existing merge.
