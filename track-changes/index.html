What is track-changes?

track-changes is a skill for Claude Code that intercepts every Write / Edit / MultiEdit on tracked .md, .qmd, and .tex files. Each AI-introduced change is wrapped in a <mark> highlight followed by <sup>N</sup> — rendered yellow with strikethrough overlay in any markdown viewer — so you can review every change individually and accept or reject it the way you would in Word or Google Docs.

Why it exists

Vetted source documents — lecture notes, exams, manuscripts — have often been reviewed by their author for years. Silent AI-introduced changes destroy that trust. The PreToolUse hook refuses any edit to a tracked file that doesn’t wrap the differing characters in a numbered mark. The PostToolUse hook appends every mark (and every later resolution) to a project-local .tc-history.md audit log that lives in git.

Prerequisites

Claude Code must be installed and working. track-changes is a Claude Code skill — it runs inside Claude Code, not separately. Install Claude Code first if you haven’t already. The skill also needs Python 3 and curl (both default on most setups).

Installation

  1. Start a Claude Code session — anywhere; track-changes installs to your user profile, not a specific project.
  2. Give the bootstrap URL to Claude Code. Type:
    Read https://mgkay.github.io/track-changes/bootstrap.md and follow the installation instructions inside it.
  3. Confirm the installation. Claude Code downloads the skill files, merges five hook registrations into your ~/.claude/settings.json, and reports success.
  4. Open a new Claude Code session so the registered hooks take effect.

Updating. Run the same install command again. The installer reads the current ~/.claude/skills/track-changes/VERSION and only overwrites if the remote version is higher. The settings.json merge is idempotent.

Activate tracking on a folder

The skill is OFF by default — it ignores every file until you explicitly opt in. The most common activation: you create an empty file named .tc-tracked in the folder containing your source files. There is no such file anywhere by default; the skill checks the file’s own folder at edit time and only activates if this marker is present.

Three ways to create the marker:

  • From any shell: touch /path/to/lectures/.tc-tracked
  • From Claude Code: /tc mark /path/to/lectures (writes a self-documenting marker)
  • Without a folder marker, per-file: add track-changes: true to a .md / .qmd file’s YAML frontmatter, or invoke /tc enable <file>

The marker is checked in the file’s own folder only — no walk-up, no descent into subfolders. To track files in a subfolder, drop a separate marker there. Hidden files (basenames starting with .) are excluded by default.

Both decisions, with timestamps and old/new strings, are appended to <git-repo-root>/.tc-history.md — the audit log lives in git, so git diff, git blame, and PR review all surface AI-attributed changes naturally.

What you get

Hooks (registered in settings.json)

  • PreToolUse validates every Write / Edit / MultiEdit on a tracked file. Blocks if any diff region isn’t inside a <mark>.
  • PostToolUse diffs current marks vs prior cache; appends introduced + resolved entries to .tc-history.md.
  • SessionStart surfaces a LaTeX-preamble advisory when editing .tex files.
  • Stop / UserPromptSubmit manage the /draft per-turn sentinel.

Slash commands

  • /draft — suspend tracking for the next turn (e.g., for a large refactor that’s too noisy to mark).
  • /tc enable <file> / /tc disable <file> — per-file YAML frontmatter writer.
  • /tc mark [<dir>] — drop a .tc-tracked marker.
  • /tc status [<file>] — inspect the activation chain.
  • /tc migrate <dir> — convert v1 marks to v2 in place.

Performance

Per-tracked-edit overhead is ~154ms on Windows + Git Bash, split between the validator hook (~75ms) and the audit-log hook (~79ms). Both are written in native Python and share an optional persistent daemon (lib/tc_daemon.py) that auto-spawns on first call and keeps analyzer state warm for the rest of the session. Test suite: 198 tests in ~7s under parallel mode.
